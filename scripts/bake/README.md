# Static indirect lighting

Toolchain: Blender **5.2.2 LTS**, Cycles, glTF-Transform **4.5.1**, and the existing Playwright installation. No additional packages. `BLENDER` may override the executable location; `cwebp` must be installed.

`pnpm bake corridor`, `pnpm bake office`, `pnpm bake codex-room`, `pnpm bake exchange`, and `pnpm bake apartment` start an isolated development page on port 5186, export the mounted runtime scene into ignored `.bake-cache/`, run Blender, and encode the atlases. Set `BAKE_PORT` when 5186 is already serving this same worktree. The production entry never imports the bake page. Exchange uses a 2048² switchboard/upper-gallery atlas plus a 1024² desk/threshold atlas and a 1 MB combined WebP ceiling. Apartment uses a single 2048² stage atlas.

Static is the default. Tag the highest moving ancestor `userData.bake = 'dynamic'`; descendants are excluded. Transparent and unlit surfaces remain runtime geometry. Animated lights may illuminate the baseline bake but never enter the static geometry. Geometry IDs derive from geometry and world transforms, rather than names or traversal order. Re-imported baked geometry replaces only the matched static geometry, retaining the live material and mesh transform.

The asset contract and light calibration are described in ADR 0008. Re-bake after geometry, light, material reflectance, emissive or texture-transform changes. Material fingerprints include effective UV transforms, texture channels, colour space, wrapping and filters. Roll back the integration commit and its baked assets together.

The export browser uses native Metal WebGL on macOS; `BAKE_BROWSER_ANGLE=swiftshader` opts into software rendering, whose high-tier readiness can exceed browser-test startup timeouts on this host. Other platforms default to SwiftShader. Background Cycles Metal enumeration succeeds here but even a 32×32 receiver test stalls during execution. CPU is the reproducible default for this session; `BAKE_DEVICE=GPU pnpm bake corridor` opts into Metal on a validated host. The denoiser uses Blender's bundled OpenImageDenoise CPU library. Point and spot calibration measures both engines and fails above 3% disagreement. The corridor's analytic-lamp conversion is matched at 2 m; its softened core/tail and three's smooth distance cutoff differ from Blender's physical emitter and hard cutoff. Those approximations require visual approval.

Freshness uses the source-file fallback: a SHA-256 `sourceHash` over raw authored bytes, never rendered pixels, browser image dimensions, system fonts, clock values, locale, absolute paths or file metadata. `scripts/bake/inputs.mjs` defines the stable file scopes. The shared file list includes `apps/web/bake.html`, whose entry page wires the scene used by every room's bake:

- Per space: all production files under `apps/web/src/corridor/`, `apps/web/src/chambers/certification-office/`, or `apps/web/src/chambers/annex-codex/`. Exchange also includes `apps/web/src/chambers/exchange/`, `scripts/blender/rooms/exchange/`, and its committed `exchange.glb` and `exchange.glb.gz` models. Apartment includes `apps/web/src/chambers/apartment/`, `scripts/blender/rooms/apartment/`, and its committed `apartment.glb` and `apartment.glb.gz` models.
- Shared: all production files under `apps/web/src/assets/`, `apps/web/src/audio/music/`, `apps/web/src/bake/`, `apps/web/src/firstPerson/`, `apps/web/src/look/`, `scripts/bake/`, and `packages/engine/src/`; the frozen `pnpm-lock.yaml`; `apps/web/src/baked/contract.ts` and `lights.ts`; `apps/web/src/main.tsx`, `App.tsx`, `environment.ts`, `routes.ts`, `pageScroll.ts`, `sceneFrame.ts`, `timing.ts`, `chambers/registry.ts`; every chamber's `door.ts`; and `packages/ui/src/contextualCues.ts`.
- Fonts: each `@fontsource` CSS import in `main.tsx` and every font file referenced by that CSS, by actual bytes from the frozen installation.

Directory scopes include additions and removals of JS/TS modules, Python sources, JSON, CSS, GLB/glTF/BIN/GZ, PNG/JPEG/WebP/SVG/AVIF and WOFF/TTF/OTF inputs. Dotfiles/directories, `__pycache__`, bytecode, README files, test/spec/integration files and the named test helpers in `inputs.mjs` are excluded. Model GLBs, image files, canvas drawing instructions/text/layout, geometry/material/light definitions and locked dependency versions all participate. The shared asset scope is deliberately conservative: even an unused library asset change requires all four rooms to be rebaked. Page CSS, public marketing assets, generated bake outputs and cache directories do not participate.

Paths are relative with `/` separators, deduplicated and sorted by code point. The digest starts with `tqw-bake-source-v1` plus NUL; each file uses decimal byte-length framing for its path and contents. The resolved list and hash are written to ignored `.bake-cache/<space>-inputs.json` for comparison. Missing inputs, missing `sourceHash`, a changed byte, or incorrect atlas encoding fail the hard gate with committed/current hashes. `pnpm check:bakes`, `pnpm test` and the web build check these same bytes without launching a browser or Blender. The export's geometry/material/baseline fields remain bake diagnostics and runtime geometry identity; they are not the portable release freshness gate. A new source scope must be documented here and both spaces rebaked.

The corridor uses a 1860×930 atlas to stay below its 400,000-byte WebP ceiling while retaining the enforced 16 texels/m near-camera minimum; the measured output density is recorded in its manifest. Chart allocation targets 24 texels/m near the camera and 12 in distant architecture. Office charts target 32 texels/m, 64 at the desk, and 12 in the archive. Packing is followed by measurement and fails below the brief's minimum densities. Corridor gutters are four pixels with two-pixel dilation; Office gutters are eight pixels with four-pixel dilation. Irradiance maps use single-level linear filtering, so coarse mips cannot blend neighbouring charts. The distant corridor polygons have degenerate UV1 at a protected black texel and keep the existing runtime lighting.

Geometry quantization uses 12-bit position, 8-bit normal, 16-bit UV and 8-bit colour. Position bounds remain within 13 mm over a 100 m span; normals remain within 0.015 radians. Out-of-unit-range TEXCOORD_0 values are stored as normalized 16-bit values with their exact per-mesh range in node extras, then restored before bake binding. This preserves tiled texture coordinates without a WebAssembly decoder. Splitting copies only each mesh's accessor bytes and necessary parent nodes. Inline JSON imports carry gzip-compressed glTF; the browser's built-in DecompressionStream expands it before GLTFLoader.parse, without fetch or WebAssembly. Each tracked file stays below the public-file size gate; compressed geometry bytes are reported separately from lightmap bytes.


The encode stage uses the sRGB transfer curve over irradiance/scale; standard sRGB texture decoding restores linear values before `lightMapIntensity` restores scale. `pnpm test:bake-toolchain` runs the actual Blender encoder and WebP codec, checks their bytes against reference codes, and reconstructs HDR values. It requires Blender and `cwebp` and fails when either is missing. Generic `pnpm test` runs the same byte/decode assertions on a tiny recorded fixture, without those offline tools. The fixture records SHA-256 hashes of the encoder and WebP flags, so edits to either fail CI until validated and refreshed with `UPDATE_BAKE_CODEC=1 pnpm test:bake-toolchain`. This keeps ordinary Ubuntu CI portable without silently skipping the codec guard. Material `lightMapIntensity` is an authored gain multiplied by the encoding scale. The Office floor and concrete use a gain of 64; steel and dark furniture use 4. These are art-direction controls, not a change to calibrated light-unit conversion.

Moving mechanisms are excluded as receivers but exported in their default pose as baseline occluders and reflectors. Moving lights contribute their default-pose indirect illumination. The source fingerprint checks that default-pose geometry/lighting definitions require a new bake when changed. Runtime freshness compares static geometry/lights, so a visitor's current lamp aim or mechanism state cannot reject the baseline. Baseline indirect from a moving light does not follow its aim; direct light and specular do. Review that approximation when lamp behavior changes.

`pnpm test` and the web build enforce freshness. The workbench uses the same committed scene wiring as the production runtime and disables HMR during deterministic exports. Production builds use the ordinary Vite entry and never include `bake.html` or the workbench code.

The workbench uses a fresh browser context and reduced motion, pins browser time for local-time clock/board geometry, freezes the scene after its first rendered frame, then waits for mesh membership to settle for 500 ms. Animated props must provide a stable resting pose under reduced motion; interactive state is never loaded from a visitor session. WebP uses `-lossless -near_lossless 70 -z 9`; encoded pixels may change by up to two steps and the actual atlas error is measured in the evidence.

The corridor encoding uses at least 8 irradiance units of range, expanding if its measured maximum is higher. This keeps dark-band quantization consistent across packing changes and retains headroom; it does not change reconstructed lighting intensity.

The export flattens complete world transforms into vertex positions/normals before Blender import. Blender's object transform decomposition drops shear from nested rotation under nonuniform scale; retaining those matrices clipped the Office's thin inset displays. Mirrored transforms reverse winding at both export and local rebinding. Animated mapped Standard materials must freeze their canvas pixels during handover; geometry, material parameters and light metadata are cloned before asynchronous hashing.

Corridor readiness waits for the first completed baked draw, including texture upload and shader compilation. Camera telemetry begins after that readiness signal. Each pose carries the frame timestamp used to advance movement; browser speed guards read that paired clock because observer delivery includes variable render delays. Missing/nonfinite pose timestamps fail the recorder. This measures simulation speed, not frame presentation smoothness. Both lite and full tiers use the maps; explicit `bake=off` is reserved for comparison captures. The one-shot scene render callback is restored on completion or unmount.
